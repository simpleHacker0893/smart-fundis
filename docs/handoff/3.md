## What changed
- `web/proxy.ts`: `clerkMiddleware` with Clerk's recommended matcher. It redirects signed-out visitors away from `/dashboard` and anything under it (D-14).
- `web/lib/auth-routes.ts`: the sign-in, sign-up and after-auth paths, plus `isProtectedPath`. Only `/dashboard` is protected for now.
- `web/app/layout.tsx`: `ClerkProvider` inside `<body>`, wrapping `NextIntlClientProvider`.
- `web/app/dashboard/page.tsx`: calls `auth.protect()`, then shows "Signed in as {email}" from `en.json`. #4 swaps `currentUser()` for Convex `users.me`.
- `web/app/sign-in/[[...sign-in]]`, `web/app/sign-up/[[...sign-up]]`: Clerk's `<SignIn />` and `<SignUp />`.
- `web/next.config.ts`: loads the **repo-root `.env`** (D-13) with `loadEnvConfig(..., forceReload=true)`. `NEXT_PUBLIC_CONVEX_URL` falls back to `CONVEX_URL`, and `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` falls back to `CLERK_PUBLISHABLE_KEY`.
- `web/test/`: route-protection tests, a matcher test checked against real paths and mutation-tested, copy tests for `/` and `/dashboard`, and shared copy helpers. `web/vitest.config.mts` has `testTimeout: 30_000` for cold Clerk imports.
- `@clerk/nextjs` moved from the root into `web`, and `@next/env` is pinned in `web`.
- Docs: D-13 (root `.env` only), D-14 (two guards), `HF_TOKEN` in PRD §7, and stale lines fixed in the #1 spec, README and `.env.example`.

## How to verify
1. `pnpm typecheck && pnpm lint && pnpm test && pnpm build` from the root.
2. `pnpm dev`, then:
   - `curl -s -o /dev/null -w "%{http_code}\n" localhost:3000/` returns `200`
   - `/sign-in` returns `200`
   - a signed-out `/dashboard` returns `307` to `/sign-in?redirect_url=…`
3. In a browser at 360 px, sign in with Google and then with an email code. Both should reach `/dashboard` and show "Signed in as <email>".

## Human step: getting the Clerk keys into the root `.env`
All local secrets live only in the repo-root `.env` (D-13). Either copy the keys from Clerk dashboard → API keys into the root `.env`, or, from the repo root:
```bash
pnpm dlx clerk@latest login
pnpm dlx clerk@latest env pull     # writes the keys into the root env files; the web app loads both .env and .env.local
```
The names are `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` (or `CLERK_PUBLISHABLE_KEY`) and `CLERK_SECRET_KEY`.

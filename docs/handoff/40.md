## Operator decisions
- **2026-09-27, in the #40 comment:** store the clip's file name (`clipName`) so the stub can follow #36 decision 1.
- **2026-09-27, after RAI S1 and S2:** everything stub-related sits behind a **dev-only Convex flag, `AI_STUB_ENABLED=1`**, which is never set on prod. The flag gates two things:
  - **S1:** without the flag, `clipName` is not stored and not sent. A file name can carry personal data (for example "Wanjiru 0722… socket.mp4").
  - **S2:** without the flag, the stub can't claim or post results, so canned outcomes can never reach a real Fundi or Expert. The worker also refuses to start unless `CONVEX_DEPLOYMENT` is `dev:`.

## What changed
**Convex**
- `convex/schema.ts`: `assessments.clipName?`. It is never returned to the web and never logged. Video deletion (V4) must unset it.
- `convex/lib/assessmentUpload.ts`: `normalizeClipName` trims the name, truncates it to 200 characters by code point (so it never splits an emoji) and turns a blank name into none. A long name is never a reason to reject.
- `convex/lib/aiStub.ts` (new): `isStubEnabled()` (the flag is on only when it is exactly `"1"`, read at call time) and `isStubName()` (`/^stub/i`).
- `convex/assessments.ts`: `create` takes an optional `clipName`. It stores it only when the flag is on, and otherwise ignores it silently.
- `convex/aiJobs.ts`:
  - `buildJob` adds `clipName` only when the flag is on.
  - `callback` returns `stub_disabled` and writes nothing when the flag is off and either the result's `model` starts with `stub` or the Assessment was claimed by a `stub*` worker. This check runs before the stale check.
- `convex/http.ts`: `/ai/claim` returns 403 for a `stub*` `workerId` without the flag. A `stub_disabled` result becomes a 403.
- `convex/lib/aiContract.ts`: `jobValidator.clipName?`, and the doc comments list the 403.

**Web**
- `web/app/(site)/fundi/record-step.tsx`: the upload sends `clipName: file.name`, or leaves it out when the name is empty.

**ai-service (gpu-devops)**
- `ai-service/scripts/stub_worker.py` (new), which uses stdlib `urllib`, so there is no new dependency:
  - It polls `/ai/claim` with exactly `Authorization: Bearer <secret>`.
  - It picks the canned outcome from `clipName`. A name containing `reshoot` gives `reshoot`/`too_dark`; otherwise one containing `review` gives `needs_review` with one safety item `unclear` and flagged, and liveness `unclear`; anything else gives `pass`. `reshoot` wins when both words appear.
  - It posts to `/ai/callback`.
  - The worker id always starts with `stub-`.
  - Every text starts "Stub result: no AI ran.". `confidence` is 0, `model` is `"stub-v1"`, `fallbackModel` is false, and every Rubric item appears exactly once. The text is English only: no `feedbackSw` and no `reason.sw` (D-64).
  - It never logs the video URL, the secret, the job or the clip name.
- `ai-service/app/settings.py`: `convex_deployment` (read from `CONVEX_DEPLOYMENT`, D-13 loading).
- `ai-service/tests/test_stub_worker.py` (new) runs against a fake Convex site in a thread.
- `ai-service/README.md`: the "Stub worker (V1, #40)" section covers the rule, the guards, the prerequisites, how to run it and the exit codes.

## Contracts / interfaces introduced
- `api.assessments.create({ …, clipName?: string })`: returns and error codes are unchanged. `clipName` is stored only when the deployment has `AI_STUB_ENABLED=1`.
- `POST /ai/claim`:
  - The 200 job gains `clipName?`, sent only with the flag and only when the row has one.
  - **403** `{ "error": "stub_disabled" }` for a `workerId` matching `/^stub/i` without the flag. Nothing is claimed.
- `POST /ai/callback`: **403** `{ "error": "stub_disabled" }`, with nothing written, when the flag is off and either the result `model` matches `/^stub/i` or `claimedBy` matches `/^stub/i`. This is checked before the 409 stale check.
- The order on both routes is 401, then 400 (body), then 403.
- CLI: `uv run python scripts/stub_worker.py [--once] [--poll-interval S] [--worker-id ID] [-v]`. Exit 0 on Ctrl-C or after `--once`. Exit 1 on 401, 403, a non-`dev:` deployment, or bad settings.

## Env vars / manual setup
- **New Convex env var `AI_STUB_ENABLED`.** Set it on the **dev** deployment only with `pnpm exec convex env set AI_STUB_ENABLED 1`. **Never set it on prod.**

- `CONVEX_DEPLOYMENT=dev:…` goes in the root `.env`; `convex dev` writes it.

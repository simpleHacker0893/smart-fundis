## What changed

  - `generateUploadUrl`, `newLivenessCode` and `currentLivenessCode`.
  - `create`, which returns `{ok:true, assessmentId} | {ok:false, code}` and deletes the file on every rejection. A throw would roll the delete back, so it returns instead.
  - `listMine`, which never returns the video.
  - `get`, which is owner only and returns `videoUrl`.

## Contracts / interfaces introduced
- `api.assessments.create({ storageId, tradeSlug, taskSlug, consentVersion?, clientConsent?, livenessCode?, previousAssessmentId? })` returns `{ ok: true, assessmentId } | { ok: false, code }`. The codes are `not_signed_in | no_user | not_fundi`, `file_missing | file_in_use | too_large | wrong_type`, `consent_missing | consent_outdated | client_consent_missing`, `unknown_task`, `liveness_missing | liveness_mismatch | liveness_expired`, and `invalid_previous`.
- `api.assessments.listMine({})` returns `{ _id, _creationTime, status, tradeSlug, tradeName, taskSlug, taskName, reshootReason?, previousAssessmentId? }[]`, newest first.
- `api.assessments.get({ assessmentId })` returns the owner's detail with `videoUrl`, or `null`.
- `api.assessments.newLivenessCode({})` returns a string. `currentLivenessCode({})` returns `{ code, expiresAt } | null`. The TTL is 2 h.
- `api.trades.uploadPicker({})` returns `{ slug, name, onProfile, tasks: [{ slug, name, rubricVersion, needsClientConsent, items: [{ id, text, safety }] }] }[]`.
- `api.fundiProfiles.setShowcaseLinks({ youtube?: string|null, tiktok?: string|null })` returns `null`. It throws `ConvexError({ code: "invalid", fields })` with `unsupported | tiktok_short | wrong_site`. `myShowcaseLinks({})` returns `{ youtube, tiktok }`, each `{ id, url, embedUrl } | null`.
- Guards: `checkFundi` (non-throwing) and `isStorageReferenced`.

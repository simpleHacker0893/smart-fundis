## What changed
**Convex**
- `convex/fundiProfiles.ts`:
  - **`getPublic({ id })`** is public by design, with no guard, and is on the public-reader allow-list.
    - `normalizeId` means a garbage id, or an id from another table, returns null.
    - It also returns null when the profile is missing, when the Fundi is not Listed (`publicListing` off), or when the user row is missing.
    - It returns `{ id, name, county, isDemo, trades[{slug,name}], badges[{tradeSlug,tradeName,taskSlug,taskName,decidedAt}] }`.
    - A Badge is an `approved` Assessment whose **latest `reviews` row is an approve**. Its `decidedAt` is that row's `at`, and Badges are sorted newest first.
    - It reads through the `by_fundiUserId_and_status` index, newest first, with `.take(200)`.
  - **`myProfileId({})`** returns the caller's own `{ id, publicListing }` or null. It never throws (it uses `checkFundi`).
- `convex/lib/decisions.ts` (new): `latestDecision`, moved out of `assessments.ts` so that `listMine` and `getPublic` date a Badge the same way.

**Web**
- `web/app/(site)/f/[id]/`:
  - The server page calls `preloadQuery`, then `notFound()` on null.
  - `public-profile.tsx` renders with `usePreloadedQuery`, so the page stays live. It shows:
    - the name, county and "Trades (declared by the Fundi)";
    - each Badge as exactly "Verified by Smart Fundis — <Trade>: <Task> · <date>" (Nairobi time);
    - "Not yet verified" in dim text when there is no Badge;
    - the "Demo: not a real verification" tag.
  - `not-found.tsx` never says why a profile is missing.
  - `error.tsx` never shows the error text.
  - The metadata sets `robots: noindex, nofollow` until the V3 visibility toggle ships.
- `web/app/(site)/fundi/fundi-home.tsx`: a "View my public profile" link (48 px) to `/f/<id>`. When the profile is hidden, a plain line shows instead.
- `web/app/(site)/onboarding/onboarding-form.tsx`: a "Shown on your public profile." hint under the name and county fields (`aria-describedby`).
- `web/app/(site)/privacy/page.tsx` and `web/messages/en.json`:
  - The consent and Privacy line now reads "Your Badges, name, county and trades are on your public profile. Your video and the review notes stay private." `CONSENT_VERSION` stays `consent-v1`, because it has never shipped.
  - The "Who sees what" table has a new "Name, county, trades" row.
  - The "Visibility" control now says "ask us through the Contact page. A toggle is coming soon."
  - All strings are English only (D-64).
- `web/e2e/full-loop.spec.ts` (new) and `web/e2e/dev-deployment.ts` (new): the full V1 demo at 360 px.
  - Children run with an allow-listed env; `CLERK_SECRET_KEY` never reaches them.
  - The skip check is lazy and happens in `beforeAll`.
  - The Badge regex is built from `en.json`.
  - The Expert opens `/expert/<id>` directly, because leftover rows can push this run's row past the queue's 50-row cap.

**ai-service**
- `ai-service/scripts/stub_worker.py`:
  - **`--hold-seconds S`** (0–300) keeps a claimed job in `analyzing`, so the e2e can see the chip change live.
  - **`--max-jobs N`**.
  - Both have tests and README entries.

## Contracts / interfaces introduced
- `api.fundiProfiles.getPublic({ id: string })` returns `null | { id: Id<"fundiProfiles">, name, county, isDemo: boolean, trades: {slug,name}[], badges: {tradeSlug,tradeName,taskSlug,taskName,decidedAt:number}[] }`. It is public.

## What changed
**Convex**
- `convex/schema.ts`: the V1 tables, with indexes named `by_a_and_b` per the Convex guidelines. §5's short index names are mapped in a comment.
  - `fundiProfiles`, `experts`, `trades`, `rubrics`, `assessments` (adds `claimedBy`, `strengths`, `gaps`), `reviews`, `auditLog`.
  - New indexes: `assessments.by_fundiUserId_and_status` and `by_rubricId`, and `users.by_email` (used by the seed only).
- `convex/lib/auth.ts`: `getRoles` derives Fundi (a profile exists) and Expert (an active row with approved Trades). Also adds `requireStoredUser`, `requireFundi`, `requireExpert(trade?)`, `getFundiProfile` and `getActiveExpert`.
- `convex/users.ts`:
  - `me` returns `null` when signed out.
  - `store` no longer overwrites the name typed at onboarding once a Fundi profile exists.
- `convex/fundiProfiles.ts`: `create({ name, phone, tradeSlugs, county })` takes 1–62 Trades. Errors are ConvexError codes.
- `convex/trades.ts`: `list` returns `{ slug, name, category, verifyNow }[]`, 62 of them, in catalogue order.
- `convex/lib/tradeCatalogue.ts`: the **62-Trade Kenyan catalogue** (operator change 2), with no Rubric text. It exports `TRADE_ROWS`, `TRADE_SLUGS`, `TRADE_LICENCE`, `TRADE_COUNT` and `tradeOrder`.
- `convex/lib/trades.ts`: Tasks and Rubrics only (`TRADE_TASKS`, `TRADE_CATALOGUE` for the seed).
- `convex/seed.ts`:
  - `seed.trades` (idempotent) seeds 62 Trades and 2 Rubrics. It rewrites a Rubric version in place only while no Assessment references it; otherwise it throws `rubric_frozen`.
  - `seed.expert` is dev only: it needs `ALLOW_DEV_SEED=true` and writes an `auditLog` row.
- `convex/lib/{counties,phone,fundiProfile,validators}.ts`: the 47 counties, the Kenyan phone rule (shared with the contact form), the form rules, and shared validators.

**Web**
- `/onboarding`: the minimal Fundi form. The Trade picker has:

- `/fundi`: an unstyled Fundi page behind the reusable `pageGuard`.
- Proxy: sign-in is required for `/onboarding`, `/application-pending`, `/fundi`, `/expert` and `/admin`.
- `web/messages/en.json`: the `Onboarding`, `DashboardPage`, `FundiPage` and `TradePicker` namespaces, and `TradeCatalogue.<slug>.{name,description}` for all 62 Trades. Everything is English only (D-64).
- Shared UI: `components/loading-skeleton.tsx` and `components/ui/field-label.ts`.
- Playwright: `web/playwright.config.ts` (a 360×800 project), `web/e2e/`, and `@clerk/testing`. Each run creates a throwaway dev user and deletes it afterwards.

## Contracts / interfaces introduced
- `api.users.me({})` returns `null | { user, roles: { base: "fundi" | "none", expert, admin } }`. V7-1 (#46) changes the roles to four booleans.
- `api.fundiProfiles.create({ name, phone, tradeSlugs: string[], county })` returns `Id<"fundiProfiles">`. Errors: `no_user`, `already_exists`, or `invalid` with `fields.{name, phone, tradeSlugs, county}`.
- `api.trades.list({})` returns `{ slug, name, category, verifyNow }[]`.
- Guards: `requireStoredUser`, `requireFundi`, `requireExpert(ctx, tradeSlug?)`.
- Web: `pageGuard(me, holds)`, and `dashboardPath` plus `BUILT_ROLE_ROUTES`.

# V2 — Real AI

- **Spec issue:** not published yet

## Demo at the end
The same upload as V1, but the Brev worker processes it:
- Real Observations appear, each with evidence and a timestamp.
- The Expert taps one and the video jumps to that moment.
- If the paper code is wrong, the result shows `livenessCheck: unclear` and `needs_review`.
- If vLLM is stopped, the 2B model takes over and `fallbackModel` is true.
- If Redis is stopped, `QUEUE_MODE=inline` still works.

## In scope
- **Brev:** `serve_vllm.sh` (8B, plus a 2B switch), Redis, `up.sh`, and `/health` reporting the model, Redis and the queue mode.
- **Pipeline:** the LangGraph graph `ingest → guard → observe → assess → rules`. Also `video.py` (a probe with OpenCV), `cosmos.py` (the `openai` SDK, `video_url`, fps 4, `liveness_digits`), `nemotron.py` (structured output), `rules.py` (spec §6), and the versioned prompts.
- **Self-hosted Nemotron client (added by V2-30; D-32, V2-Q48):** Nemotron 3 Nano 30B-A3B served by vLLM on the Brev box, reached through a LangChain chat model on vLLM's OpenAI-compatible endpoint, replacing `ChatNVIDIA` in `nemotron.py` (structured output via `response_format: json_schema`, `enable_thinking: false`). The hosted `ChatNVIDIA` path stays only as a fallback behind a setting, and `NVIDIA_API_KEY` stays on the box only while that fallback exists. Owners: gpu-devops (serving, GPU memory beside Cosmos) + ai-pipeline (the client). The V2-track V10 (Job pre-fill) is blocked by it.
- **Queue:** `poller.py` and the Celery `worker.py`, with the `QUEUE_MODE` switch, and `callback.py` with retries.
- **Tracing:** LangSmith masking.
- **UI:** the Expert review shows the Observations, jumps to timestamps, and shows `livenessRead` next to the expected code.

# V1 — Tracer bullet (the loop, with a stub AI)

- **Spec issue:** #36 (tickets #37–#43)
- **Lane:** A (convex + frontend), plus a small stub-worker script · **Blocked by:** V0 · **Time box:** to H+2:30

## Demo at the end
1. A Fundi (whose profile was created by a minimal form) picks **Electrical → Install a 13A socket**.
2. They see the Rubric and the Liveness code, accept the verification consent (English and Kiswahili), then record or pick a video on the phone. The upload shows progress.
3. The chip goes `queued → analyzing → awaiting_review` without a refresh.
4. The **stub worker** claims the job through `/ai/claim` and posts a canned `result` to `/ai/callback`.
5. A seeded Expert opens `/expert`, sees the Assessment and the canned Observations, and approves it.
6. `/f/[id]` shows "Verified by Smart Fundis — Electrical: Install a 13A socket · <date>".

## In scope
- **Schema:** `fundiProfiles` (minimal), `experts`, `trades`, `rubrics`, `assessments`, `reviews`, `auditLog`.
- **Seed:** both Trades, both Rubrics, and one Expert. The Rubric texts must be checked by rai-reviewer.
- **Consent:** the verification consent screen in English and Kiswahili (unstyled), stored as `consentVersion` and `consentAt`. Upload stays disabled until it's ticked. This is never cut.
- **Upload:** `generateUploadUrl`; `assessments.create` with server validation (US-3.9) that deletes invalid files; `newLivenessCode`; `listMine`; the detail query (which returns the URL).
- **The claim and callback HTTP actions** with the full spec §6 contract: secret, 204, atomic claim, 409 on a stale callback. Plus the requeue and fail cron.
- **The stub worker:** `ai-service/scripts/stub_worker.py`, which uses the same contract, returns a canned result, and is safe to run against dev.
- **Expert:** `reviews.queue` and `reviews.decide` (approve/reshoot/reject with a note) using `canDecide`, and the Badge derivation.
- **Screens:** unstyled but usable `/fundi`, the upload flow, `/expert` and `/f/[id]`. Stitch styling comes in V3.

## Grill focus

3. Edge cases in the claim race: two pollers, a callback after the cron has requeued, a callback for a deleted Assessment.
4. What the Fundi sees for each status, including `reshoot` from the stub.
5. Where the seeded Expert comes from: seeded, or the V4 approval flow faked by an internal mutation.
6. The final consent text in English and Kiswahili, its version string, and who checks the Kiswahili.

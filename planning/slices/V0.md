## Demo at the end
On a phone, the Vercel preview URL loads an empty branded shell. The user signs in with Google, and `/dashboard` shows "Signed in as <email>". The Convex dashboard shows the new `users` row.

## In scope
- The monorepo from PRD §2:
  - npm workspaces for `web` and `convex`
  - `convex.json`
  - a folder structure for `ai-service/`
  - `.gitignore`
  - `.env.example` listing every variable name from PRD §7
- A Next.js App Router app with no `src/`, plus Tailwind, shadcn, `next-intl` with `en.json` only, and Plus Jakarta Sans.
- Convex with an initial schema of only `users`. It also needs `auth.config.ts`, `users.store` and `users.me`, and `lib/auth.ts` with `requireUser` and `getRoles` (stubbed to Fundi = none).
- Clerk (development instance) with `ClerkProvider` and `ConvexProviderWithClerk`, and a proxy that requires sign-in on `/dashboard`.
- The CI workflow runs on the first PR.

## Grill focus
1. `ai-service` tooling: Python version, package manager (uv or pip), and a folder for the `pytest` fixtures.
2. Tooling for `web` and `convex`: the test runner (Vitest for `convex-test`), lint (ESLint config), and Playwright installed now or in V1.
3. When the JWT template gets `email_verified`, and what `requireUser` does before `users.store` has run (a first-render race).
4. The Vercel project root, and whether Convex deploys from CI or only by hand. ADR: only the Architect deploys prod.

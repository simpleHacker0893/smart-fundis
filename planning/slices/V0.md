## Demo at the end
On a phone, the Vercel preview URL loads an empty branded shell. The user signs in with Google, and `/dashboard` shows "Signed in as <email>". The Convex dashboard shows the new `users` row.

## In scope
- The monorepo from PRD §2:
  - a pnpm workspace (D-12) with `web` as its only package; `convex/` is a plain functions folder with its deps at the root (D-11)
  - `convex.json`
  - a folder structure for `ai-service/`
  - `.gitignore`
  - `.env.example` listing every variable name from PRD §7
- A Next.js App Router app with no `src/`, plus Tailwind, shadcn, and `next-intl` with `en.json` only.
- The brand comes from D-9 (`design/stitch/DESIGN.md`): graphite, text and amber tokens, the system/Inter display stack and JetBrains Mono for readouts. It is **not** Plus Jakarta Sans or green/orange. The empty shell is just the header and footer, built as `design/HANDOFF.md` says (the REFERENCE export and `02-evidence-responsive`, **not** the retired `00-header-footer-mobile`), with no motion yet.
- Convex with an initial schema of only `users`. It also needs `auth.config.ts`, `users.store` and `users.me`, and `lib/auth.ts` with `requireUser` and `getRoles` (stubbed to Fundi = none).
- Clerk (development instance) with `ClerkProvider` and `ConvexProviderWithClerk`, and a proxy that requires sign-in on `/dashboard`.
- The CI workflow runs on the first PR.

## Suggested ticket shape (prompt 30 decides)
1. **Monorepo scaffold** (architect): workspaces, `convex.json`, the `ai-service/` folders, `.env.example`, `.gitignore`.
2. **Next.js shell** (frontend): App Router, Tailwind, shadcn, `next-intl`, the D-9 tokens, and the header and footer at 360 px.
3. **Convex `users` and auth helpers** (convex + auth): schema, `auth.config.ts`, `users.store`/`users.me`, `requireUser`/`getRoles`, with `convex-test` tests.
4. **Wire the keys** (`ready-for-human`, wizard): `npx convex dev` creates the project; Clerk keys go into `web/.env.local`; `npx convex env set` for CLERK_FRONTEND_API_URL, ADMIN_EMAILS and AI_SHARED_SECRET; the Vercel import with root `web/` and its env vars.
5. **Sign-in round trip** (auth + frontend): the providers, the proxy on `/dashboard`, and "Signed in as <email>", checked on the Vercel preview.

## Grill focus
1. `ai-service` tooling: Python version, package manager (uv or pip), and a folder for the `pytest` fixtures.
2. Tooling for `web` and `convex`: the Next.js, Tailwind and shadcn versions (fetch them live), the test runner (Vitest for `convex-test`), lint (ESLint config), and whether Playwright is installed now or in V1.
3. The env var name for the Clerk issuer: our PRD says `CLERK_FRONTEND_API_URL`, and the live Convex docs say `CLERK_JWT_ISSUER_DOMAIN`. Clerk now sets Convex up through its "Activate Convex integration" page, not a hand-made JWT template. Also: when the token gets `email_verified`, and what `requireUser` does before `users.store` has run (a first-render race).
4. The Vercel project root, and whether Convex deploys from CI or only by hand. ADR: only the Architect deploys prod.
5. How much of the D-9 shell belongs in V0 (tokens and fonts only) and how much waits for V3 (motion, grain, Three.js).

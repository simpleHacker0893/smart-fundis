# Risks

| # | Risk | Likelihood / impact | Mitigation | Owner |
| --- | --- | --- | --- | --- |
| R-1 | Brev credits, provisioning or the model download is slow or fails on the day | M / H | The V1 stub worker keeps the loop demoable. The 2B fallback exists. Start the download at H0. | gpu-devops |
| R-2 | Cosmos can't read handwritten digits reliably | M / M | Every miss is capped at `needs_review` (ADR-19), and the Expert checks. The eval includes wrong and missing codes. Make no accuracy claim until measured. | ai-pipeline |
| R-3 | A 90 s clip at fps 4 exceeds `--max-model-len 8192` | M / H | Test one 90 s clip early in lane B. If it's too long, lower the fps for long clips (a new decision needed). The 90 s cap stays. | ai-pipeline |
| R-4 | Only 4 hours of build time if the start is 11:00 | M / H | The anchors are relative (freeze at H+4), the cut order is agreed, and V4 is optional. | architect |
| R-5 | A leaked video URL stays public | L / M | URLs come only from the detail query and claim, and are never logged. This is listed as a known limitation. | convex |
| R-6 | The Stitch tools fail or run past 45 minutes | M / M | The prompt files also work in the Stitch web app, and the fallback is plain shadcn. | frontend |
| R-7 | Stock clips miss cornrows and real socket work | H / M | The team records its own core clips (ADR-14). | architect |
| R-8 | ~~The Claude GitHub App or its secret isn't set up~~ Accepted: review is manual (D-10), so a PR can merge unreviewed if the Architect is rushed | M / M | The local `/code-review` (plus `convex-reviewer`) runs on every ticket, and the Architect reviews each PR by hand. | architect |
| R-9 | A demo seed shown as verified misleads the judges | L / H | The `isDemo` tag appears on every Badge and demo profile, and the seed is disclosed. | qa |
| R-10 | The Convex plugin hooks slow down every turn (the type-check at the end of a turn) | M / L | Watch for it. If it's too slow, disable the plugin's Stop hook for lane B sessions. | architect |
| R-11 | **Closed by D-11.** The Convex CLI bundles every `.js` under `convex/`, including a `convex/node_modules/` folder if npm can't hoist a dependency (the CLI doesn't skip it; seen in convex 1.46.0 source) | L / H | Keep `web` and `convex` on the same versions of shared deps, and never run `npm install` inside `convex/`. Ticket #4 adds a check that fails if `convex/node_modules` exists. | convex |
| R-12 | TypeScript 7 (the native Go compiler) has no classic JS API, which Next's type check and typescript-eslint need | M / M | Both workspaces pin `typescript ^6.0.3`. Don't upgrade until Next and typescript-eslint support TS 7. | architect |
| R-13 | pnpm 12 stops on unapproved dependency install scripts (esbuild, @swc/core, @parcel/watcher, unrs-resolver) | L / L | All four are set to `false` in `pnpm-workspace.yaml` `allowBuilds`, and every check passes without them. Approve one only when a tool is proven broken, by the operator. | architect |
| R-14 | The chosen Nemotron model (`nemotron-3-nano-omni-30b-a3b-reasoning`) is not on langchain-nvidia-ai-endpoints' list of models that support structured output. The #9 smoke passed, but V2's Verdict step needs reliable structured output. | M / H | Before V2, run the smoke with a listed model (`nvidia/nemotron-3-nano-30b-a3b` or `-super-120b-a12b`) and switch `NEMOTRON_MODEL` if needed: `cd ai-service && uv run python -m app.nemotron`. The V2 pipeline must treat a `None` or unparseable reply as a retry, then `needs_review`. | ai-pipeline |
| R-15 | A Fundi enters someone else's phone number (it is not OTP-verified), or a published Portfolio item shows a person who didn't agree | M / M | Phone is opt-in and revealed on tap only (ADR-21); report reasons `wrong_phone` and `shows_someone_without_consent`; Admin hide with audit; per-item people confirmation (D-22). OTP in the Pilot. | convex |
| R-16 | A mutation that changes a Badge or profile forgets to call `syncListing`, so `/fundis` shows a stale or hidden Fundi | M / H | One helper, a projection-consistency convex-test after every caller, and `listings.rebuildAll` (ADR-22). The public profile query re-checks the Listed rule. | convex |
| R-17 | Clients mistake an unverified Fundi for one Smart Fundis has vetted, now that every Listed Fundi appears (D-24) | M / H | A neutral "Not yet verified" label on every unverified card and profile; verified-first sorting; the "Verified only" chip; the profile line "Smart Fundis has not verified this fundi's work yet"; skill Badges are the only place ✓ and "Verified by Smart Fundis" appear. QA checks this with a Playwright style assertion, and rai-reviewer signs off the copy. **V2 (proposed D-44):** this mitigation is **weakened**: Fundi Pro ranks first, verified or not, so an unverified paying Fundi can appear above an Expert-approved one. Kept: the "Fundi Pro" tag and legend, the "Verified only" chip, ✓/amber only for Badges (R-36, R-37). | architect, rai-reviewer |
| R-18 | **Mostly closed by D-46 (V2):** the anonymous `visitorKey` reveal is retired; every reveal needs `requireClient`, `clients.create` is rate-limited per identity, and the 100-a-day per-Fundi cap covers Call, WhatsApp and Pay-to. What remains is harvesting through many cheap Client accounts (R-25). MVP text: without Turnstile or an IP limit, a scraper can rotate `visitorKey` and harvest opted-in phone numbers through `contact.reveal` (Q-3) | M / M | Opt-in only; the number is never in HTML or list results; rate limits of 10 an hour per visitor key and 100 a day per Fundi; the `contactReveals` log reviewed weekly; add Turnstile if bulk harvesting shows. | convex |
| R-19 | `contactMessages` stores names, emails or phones and message text with no retention limit (Kenya Data Protection Act 2019: keep personal data no longer than needed) | M / M | Add a Convex cron that archives or deletes messages older than a set period (for example 12 months) once the Admin inbox exists (V4). Until then, the operator reads messages in the Convex dashboard and deletes closed ones by hand. | convex |
| R-20 | Kiswahili AI output (`feedbackSw`, Kiswahili Job posts) is poor or wrong: no Nemotron model card lists Kiswahili (D-29, D-32) | M / H | A native-speaker check on a sample before launch, and Kiswahili clips and posts in the eval. The Fundi sees feedback only after the Expert decides. If quality is poor, fall back to reviewed template phrases per Rubric item. **Extended (V2-25 review):** also covers the Kiswahili consent strings, Client terms and the Pro legend (D-47, D-49), which are "SW draft" until a native speaker signs them off; that sign-off is needed **before V8 merges**. | ai-pipeline, rai-reviewer |
| R-21 | **Proposed (V2).** Map / geo-provider cost: a provider's per-call pricing (Google: 10k free per Essentials SKU a month, then $2.83–$7.00 per 1,000, checked 2026-09-26) grows with every search if a geocoder or map is added | L / M (V2 uses none) | No geocoder and no map in V2 (D-36); device location and a ward picker cost nothing. | R-22 | **Proposed (V2).** Provider terms: Google ToS §3.2.3(d)(iii) bars use "in a listings or directory service"; Places/Geocoding coordinates may be cached only 30 days; no use with non-Google maps | L / H if reintroduced | Google dropped from V2 (operator Q8). Counsel reads the terms before any provider is added; store only provider place ids, never provider coordinates (ADR-25). | architect |
| R-23 | **Proposed (V2).** Location privacy: a Fundi's service point reveals where they live or work; repeated near-me queries could triangulate it | M / H | Device points only, snapped once at write time to ~1.1 km; bands only, nothing below "Within 2 km"; points never returned (test #25); "your usual work spot, not your home"; delete on "Turn off location"; visitors' points never stored. | convex |
